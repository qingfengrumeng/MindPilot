# 模型对比与 RAG 评测

入口为个人账户菜单的「模型对比测试」。大弹窗顶部提供「LLM 性能对比」「RAG 评测」两个页签。

## LLM 型号对比

用户选择 1—12 个具体型号，设置 1—6 个同时请求。测试项可以来自同一厂商；例如同一 DeepSeek 凭证下的两个不同型号。添加或更换型号时，先选择已保存密钥及文本接口的厂商，再输入型号或点击获取模型列表。

列表只来自显式触发的厂商 API 请求，不使用预置型号列表，不写入配置文件或浏览器存储，关闭选择窗口即清空。已保存的型号可以作为输入框初值，但不等于已经获取可用模型列表。

各型号使用相同提示词、系统提示词和请求参数，独立显示回答、思考过程、首字耗时、总耗时、输出 token 与输出速率。没有真实用量就不计算 token 速率。测试不会切换启用模型、修改密钥或创建会话记忆。

## RAG 的两层评测

先测检索，再测回答。每个检索方案配置独立的 Embedding 型号、维度及向量协议、`chunk_size`、重叠字符、`top-k`、重排候选数，以及可选的 Rerank 型号。火山引擎下的文本向量和多模态向量可以分别选择兼容或方舟多模态协议，避免同厂商不同型号误用同一种接口。回答 LLM 和事实核验 LLM 是独立的公共配置，以便其他条件相同地对比检索方案。

每个方案进行真实向量请求，在隔离的内存向量集合中执行精确余弦检索。这里不使用正式 Chroma 集合，也不在模型失败时回退到本地哈希向量。分块长度使用字符单位，与 token 长度不同。各方案分别生成向量，报告向量耗时、查询检索耗时和重排耗时；结果受网络与运行顺序影响，适用于开发对比，不是服务吞吐量压测。

支持兼容 `/embeddings` 协议与已有方舟多模态向量适配器。百炼重排使用已有原生接口，其他已保存的重排接口使用常见 `/rerank` 请求格式；不兼容的接口会明确失败。是否有调用权限、型号是否存在、维度是否支持，由真实请求验证。获取列表接口不支持某类别时可手动输入，不编造候选项。

回答模型只接收问题与检索片段，不接收黄金答案和相关性标注。评审模型单独接收回答、检索片段和可选的黄金答案，输出事实列表及来源；服务端校验结构和来源下标后计算分数。未选择评审、无可核实事实、输出被截断或核验格式无效时，缺失的指标显示 `—`。

## 黄金测试集的迭代

1. 上传独立的 PDF、TXT 或 Markdown 测试语料。
2. 添加问题、黄金参考答案，划分开发集与测试集。
3. 给问题对应的文档标注相关等级：0 不相关、1 弱相关、2 相关、3 高度相关；未标注单独表示。
4. 添加已确认的证据页或证据片段。证据记录文档 ID、页码和规范化文本的字符区间，不依赖可变的分块 ID。
5. 测试后复核多个方案的命中资料，发现新的相关资料时补充相关性和黄金证据。
6. 保存标注，点击「按最新标注重算」。检索分数直接重算，无需再次调用模型。
7. 修改问题文本需要重新运行该问题；修改黄金答案会使原参考一致性指标失效，需要重新评审。原报告保留，并生成新的评分报告。

测试并不要求一开始列出全部相关资料。只有检查过当前语料的全部文档才能声明标注完整。未标注文档暂按 0 计算排序分数，同时展示标注覆盖率与「暂定」，不会把未知标签显示为人工判定的不相关。不同方案应在同一标注版本下比较；只使用单一方案发现的资料可能偏向该方案，建议综合多个方案的结果后人工统一判断。

开发集用于调参；测试集用于保留问题验证。两者是分组与运行过滤，不提供权限级别的标签封锁，使用者需要避免反复根据测试集结果调参。

## 指标口径

| 指标 | 当前计算方式 |
| --- | --- |
| Precision@k | 文档去重后的前 k 名中，等级 > 0 的文档数量 / k；不足 k 名仍以 k 为分母 |
| Recall@k | 命中的已知相关文档数 / 当前标注的全部相关文档数 |
| MRR@k | 第一篇相关文档名次的倒数；有相关标签但未命中时为 0 |
| nDCG@k | 折损累计增益 / 理想排序增益；增益为 `2^等级−1`，折损为 `log2(名次+1)` |
| Hit Rate | 前 k 名是否至少命中一篇已知相关文档 |
| 标注覆盖率 | 已人工标注（包含不相关）的命中文档数 / 命中文档数 |
| 证据覆盖率 | 黄金证据字符范围被检索片段覆盖的比例；重叠区间只计一次 |
| Faithfulness | 评审拆出的回答事实中，由检索内容支持的比例 |
| 参考一致性 | 回答事实中，由黄金答案支持的比例，属于事实精确率的估计 |
| 参考事实召回 | 黄金答案中的事实，被回答覆盖的比例 |

`top-k` 是最终返回的分块数；IR 指标将这些分块按首次出现的文档去重后评估，同一文档不会重复获得收益。因而命中文档可能少于 k。证据覆盖另行反映分块范围，便于在黄金标签稳定时比较不同分块大小。

没有已知相关文档时，Precision、Recall、MRR、nDCG 和 Hit Rate 不计分，避免把未完成标注当作确定的负例。Recall 的分母是已知相关文档，不是尚未发现的全部相关文档。汇总采用每个指标有有效分数的问题的宏平均；失败问题不补 0，成功、失败数量与每题结果分开显示。

Faithfulness 与参考一致性不同：回答可能忠实于检索资料，但资料本身无法给出正确答案。评审分数为模型估计，不是人类真值；界面可展开事实及证据来源供复核。当前没有测多次生成的重现稳定性，不把参考一致性称为重复运行一致性。

## 临时空间与数据隔离

```text
backend/data/
├── mindpoilt.sqlite
│   └── evaluation_workspaces   # 用户、版本、过期时间、语料页文本、黄金标注、最近 3 份报告
└── model_comparisons/
    └── rag/<workspace UUID>/   # 测试上传文件；导入测试集时保存规范化 TXT

.mindpoilt/models.json          # 仅已有模型配置与真实凭证，不保存测试语料
.mindpoilt/state_1.sqlite       # 不写入 RAG 测试空间、问答、结果
```

一个账户复用一个临时测试空间，写入操作延长为 24 小时有效期。读取不延长。程序启动或打开测试空间时清理过期空间；不是每秒定时删除。清空立即删除该空间的文件与业务库记录。最多保留 3 份完成报告；取消测试时仅保留当前界面已返回的结果，未完成报告不写入数据库。

上限：12 份文档、每份 10 MB、总计 15 万字符、20 条问题、6 个方案、每方案 1500 个分块、最终 top-k 20、重排候选数 100。单个模型网络请求有超时；取消可阻断异步生成和后续请求，已提交给同步向量适配器的单次请求仍可能持续到其超时，不能保证厂商停止计费。

测试集 JSON 导出包含规范化文档文本与黄金标注；报告导出包含结果、请求选择和版本，不包含厂商密钥。导入替换当前临时语料，重建文档 ID 并同步重写证据关联。只支持受限字段，客户端不能指定服务器路径。导出后可以在空间过期后重新导入继续优化。

业务库使用用户外键和所有权检查。调用共享模型仅允许主账户；运行时通过 `evaluation_models.py → model_preferences.py → config.py` 解析已保存凭证。配置路径、接口地址和 API Key 不接受测试客户端覆盖。乐观版本检查拒绝过时标注，运行固定输入快照，报告保存与黄金修改发生竞争时不会静默覆盖。

## API 与验证

前缀 `/api/v1/model-evaluations/rag`：创建/复用空间、读取空间、删除空间；上传/删除测试文档；保存黄金问答；导入测试集；执行 NDJSON 评测；重新计算报告的检索分数。具体路由见 [rag_evaluations.py](app/api/routes/rag_evaluations.py)。SQLite 升级新增业务表，不搬动已有账号、会话、记忆或密钥。

测试通过模拟传输验证真实适配器协议、向量检索、重排顺序、指标公式、黄金版本、无费用重算、身份隔离、过期删除及取消传播。自动化不会调用真实付费模型；实际密钥权限和厂商协议需要用户在网页执行测试确认。

## 设计依据

- [Ragas Faithfulness](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/)：通过回答事实与检索证据核验事实支持比例。当前采用自行实现的结构化核验流程，未安装或声称运行 Ragas 引擎。
- [Ragas Context Recall](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_recall/)：参考答案事实是否被上下文覆盖，与文档 Recall@k 是不同口径，界面没有将二者混用。
- [ir-measures 指标定义](https://ir-measur.es/en/latest/measures.html)：标准检索指标的截断、相关性与排序定义。
- [TREC relevance judgments](https://trec.nist.gov/data/reljudge_eng.html) 与 [NIST pooling limitations](https://www.nist.gov/publications/bias-and-limits-pooling-large-collections)：汇集多个检索方案发现的候选资料，再人工标注；有限标注可能带来偏差。因此本实现显示覆盖率、保留数据版本，并允许持续修订黄金证据。
