# 每日热点 Agent

每日热点通过后端 Agent 调用已配置的文本模型和联网搜索工具获取。前端不再直接读取 AI HOT 聚合接口，也不生成演示热点。仅在用户点击“同步热点”按钮时启动工作流，打开页面、刷新页面或列表为空时均不自动执行，没有后台定时任务。执行过程中按钮禁用，避免重复触发。

## 工作流

1. 配置仅包含热点方向 `direction` 和每次获取条数 `maxItems` 两项。默认优先检索北京时间当天的新闻，指定条数不足时再回看最近 3 天、最近 7 天；方向中指定的时间范围可由模型在 1–30 天内识别。所有轮次优先较新的新闻，第一轮查询强制加入当天日期。条数为空时继续遵循一次搜索的约定，搜索当天优先的详细报道，再按实际发布时间筛选、排序返回内容，不另行补搜。旧主题与关键词会自动合并为方向，已有用户设置保留。
2. 后端通过 `app.tools.web_search.search` 调用联网搜索工具。条数填写 1–100 时，每轮最多 4 个查询，每次最多返回 20 个来源。条数留空保存为 null，表示不设热点条数上限：仅调用一次搜索工具，分批整理全部返回来源，不补搜、不按数量裁剪。搜索工具本身的返回上限仍适用；同一事件合并、去重、时间筛选及校验可能使最终热点数量少于网页数量。模型与搜索凭证通过 `config.py` 安全配置层读取，不发送给前端。
3. 按来源明确提供的发布时间筛选，排除缺少可解析时间、过期或未来时间的网页。规范化 URL，移除跟踪参数及片段，排除已保存和本次已处理的链接。
4. 查询优先原始报道、详细新闻与深度分析，同一天内优先正文信息较丰富的来源。每页来源内容保留最多 16000 字，按每批最多 12 个来源及正文合计最多 48000 字分批整理。模型保留原始事实、限定条件、引述与主要细节；摘要建议 80–180 字，正文在证据充分时展开到约 600–1500 字。同一事件合并为 event 报道；单篇信息不足时，可将主题紧密相关的多个网页整理为 roundup 综述，分点对应单个来源并标明来源编号、各自主体与日期，不能伪装成同一事件或合并无关主题。每条最多 6 个原始链接。
5. 结果须符合结构化格式，每段正文关联来源编号与原文引文。代码校验编号和引文是否真实存在，再通过独立模型校验检查事实、主题相关性、合并与重复事件。网页内容只作为数据，不执行其中的指令。

   正文不得只有几句摘要：首次过短时依据原始来源重新展开一次，再做事实校验。新文章正文最低要求为 300 字；随着引用来源内容量增多要求提高，最高最低门槛为 600 字。不足时排除，不能用标题、分点标题或来源编号凑正文长度。综述至少关联两个来源，每点对应一个网页。检索内容不足以支持文章时，按实际合格数量保存，不编造全文。

   每个模型阶段提供合法 JSON 示例和完整 JSON Schema；支持提取代码块、说明文字包围的 JSON 及去除思考标签。格式校验失败会提供字段级错误并最多纠错重试两次，不放宽事实或引文校验。缺失 articles 或 approved 等必填字段不能视为空结果成功；仍失败时提示搜索规划、内容整理或事实校验中的具体阶段，且不保存本次内容。
6. 已填写条数时，数量不足再次规划搜索，总计最多 3 轮；超过指定条数的结果丢弃。补搜后仍不足时按实际数量保存，不编造内容、来源或日期来凑数。未填写条数时一次搜索的全部有效热点直接进入保存。
7. 校验完成后统一提交业务数据库。流程出错时不保存本次未完成的结果，已有记录保留。前端收到完成事件后更新列表。

百度工具粗粒度时效参数使用 week（最近 7 天）或 month（最近 30 天），之后仍按 Agent 规划的时间范围严格筛选日期。参数与数量上限见[百度官方文档](https://ai.baidu.com/ai-doc/AppBuilder/pmaxd1hvy)。

## 内容与来源

详细正文基于联网搜索实际返回的内容整理，不保证等于网页全文。内容不完整时不能补写缺失事实。详情分别展示摘要和完整内容，同时注明来源依据。引文匹配与模型校验有助于约束生成，但不能保证模型完全不出错。

单来源直接打开网页；多来源点击“原始来源”弹出选项框，展示标题和域名。仅标题及查看按钮进入详情，摘要、时间及空白处不可点击。编辑入口在详情中，编辑后保留多来源信息；修改主链接时同步更新第一条来源。

详情中的“保存到知识资料”将当前标题、摘要、可用正文、全部有效原始链接及发布时间生成 UTF-8 Markdown 文件，通过已有资料上传接口保存到个人学习知识域。文件进入业务目录的账户资料文件夹，资料记录进入业务数据库，状态为 uploaded（待向量化）；不自动建立向量索引。上传后提供“前往知识资料”入口。上传期间禁用按钮，本次页面中成功保存过的热点禁用重复导入；失败可重试。正文缺失时如实注明缺失，不把旧阅读建议当作正文。

删除使用应用内确认弹窗，支持取消与失败后重试。“批量处理”显示卡片左上角复选框，可全选本页、跨页保留选择并删除所选内容；点击“取消”退出并清空选择。批量接口 `POST /workbench/items/batch-delete` 一次处理最多 500 个 ID，先校验全部条目属于当前账户且为业务条目，再统一删除并清理 Wiki 关联；任何条目无效时整批不删除。

## 接口与存放

- GET/PUT `/workbench/hot-preferences`：账户偏好。
- POST `/workbench/hot-sync`：提交后台任务并立即返回任务状态。同一账户同时只能执行一次；切换页面或刷新页面不会取消任务。
- GET `/workbench/hot-sync`：查询当前账户任务状态及当前阶段。前端执行中每 1.5 秒读取状态，离开页面仅停止轮询；返回页面重新查询，恢复按钮旋转与进度提示。任务完成后重新加载热点列表。任务运行状态保存在后端进程内存中，不支持强制重启后的续跑；已保存热点仍在业务数据库中。
- POST `/workbench/hot-sync/stream`：保留的兼容 NDJSON 接口，新界面使用后台任务接口。
- POST `/workbench/items/{id}/viewed`：首次查看记录时间，重复查看不改时间。

热点与偏好属于业务数据，保存在 `backend/data/mindpoilt.sqlite` 的 `workbench_entries` 表，按账户隔离。偏好内部分类 hot-preferences，排除普通列表、关联候选、知识检索及系统计数；热点分类 hot。

标题、摘要、正文分别存放在 title、summary、body。data_json 保存 source=hot-agent、sources（链接、标题、发布时间）、兼容主链接 sourceUrl、事件标识 eventKey、发布时间、获取时间、文章类型 articleType（event/roundup）、正文来源类型与引文证据。证据按来源数组下标关联。viewedAt 区分未查看（紫色）与已查看（绿色）。列表在后端分页前和前端展示时均按新闻发布时间降序排列，无有效发布时间的旧记录回退到创建时间。前端支持搜索、查看状态筛选和每页 12/24/36/48 条分页。

模型与联网搜索密钥仍放在 `.mindpoilt` 受控配置中。热点正文与用户偏好不写入会话 JSONL 或长期记忆目录，保持业务数据与会话、记忆、密钥配置隔离。

## 验证范围

模拟模型与搜索返回的自动测试覆盖时间筛选、无日期排除、链接去重、多来源合并、跨轮次合并、补搜、超量裁剪、引文与事实校验拒绝、取消、账户隔离、重复同步、失败不保存及运行锁释放。实际线上效果取决于配置的服务与其返回质量。
